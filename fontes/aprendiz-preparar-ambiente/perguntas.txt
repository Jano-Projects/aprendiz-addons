R: A trilha **Aprendiz por dentro** ensina, do zero, como o próprio Aprendiz funciona e como recriá-lo e customizá-lo. Ela tem cinco addons, para fazer em ordem:
1. **Preparar o ambiente** (este): terminal, Python, Git, VS Code, baixar o código, rodar o app e os testes;
2. **Arquitetura e arquivos**: o mapa do projeto e o que faz cada pasta e cada arquivo;
3. **O código explicado**: módulo por módulo, com os comandos de Python que cada um usa;
4. **Como os algoritmos pensam**: normalização, Naive Bayes, BM25, TF-IDF, Fuzzy, Híbrido, TextRank e o resto;
5. **Construir e customizar do zero**: um mini-Aprendiz feito à mão e, depois, mudanças no Aprendiz de verdade.
Pré-requisitos: os addons de Fundamentos e o **Python 1 · Básico** ajudam muito. Reserve um caderno: anote o que fizer, e faça cada passo no seu computador em vez de só ler.

A: o que instalar, ferramentas necessárias

P: quais ferramentas preciso para programar no aprendiz

R: Quatro ferramentas, todas gratuitas:
- **um terminal**: já vem com o sistema (Terminal no Linux; Windows Terminal ou PowerShell no Windows);
- **Python 3.10 ou mais novo**: a linguagem do Aprendiz;
- **Git**: para baixar o código e guardar o histórico das suas mudanças;
- **VS Code** (ou outro editor): para ler e editar o código, com depurador.

O Aprendiz em si só precisa de três bibliotecas Python (FastAPI, Uvicorn e RapidFuzz, cerca de 15 MB), que são instaladas num ambiente virtual dentro da pasta do projeto, sem mexer no sistema.

F: instalar-python
A: instalar o python
Q: porque | o Aprendiz é escrito em Python | -> python-basico:instalar
P: como instalar o python para o aprendiz
P: qual versão do python o aprendiz precisa
P: como saber se o python tem fts5
R: O Aprendiz precisa do **Python 3.10 ou mais novo**, com o módulo `venv` e um SQLite com **FTS5** (a busca textual).
- **Ubuntu/Debian:** `sudo apt install python3 python3-venv python3-pip`
- **Fedora:** já vem com tudo; se faltar, `sudo dnf install python3`
- **Windows:** `winget install Python.Python.3.13` ou o instalador do python.org, marcando **"Add python.exe to PATH"**.
Confira tudo de uma vez (no Windows, troque `python3` por `python`):
```bash
python3 --version
python3 -c "import sqlite3; sqlite3.connect(':memory:').execute('create virtual table t using fts5(x)'); print('FTS5 ok')"
python3 -m venv --help > /dev/null && echo "venv ok"
```
Se não quiser instalar nada à mão, o `instalar.sh`/`instalar.bat` do Aprendiz faz essa conferência e instala o Python sozinho quando falta.

F: instalar-codigo
A: instalar pelo código, instalar.sh
Q: porque | o script cria o ambiente virtual e instala as dependências | -> python-avancado:venv
P: como instalar o aprendiz pelo código
P: como usar o instalar.sh
P: como usar o instalar.bat
P: como instalar o aprendiz no ubuntu
P: como instalar o aprendiz no fedora
P: como instalar o aprendiz no windows
P: instalar o aprendiz
R: O jeito automático, que é o mesmo que o GitHub Actions usa para testar o projeto:
- **Linux:** `bash instalar.sh --dev`
- **Windows:** dois cliques em `instalar.bat`, ou no terminal: `instalar.bat --dev`
O que ele faz:
1. confere se há um Python 3.10+ com FTS5 que consegue criar ambientes virtuais;
2. se faltar, avisa que precisa de administrador e instala (no Linux pelo apt, dnf, zypper, pacman ou apk, pedindo a senha certa: sudo, su ou a janela gráfica; no Windows baixando do python.org);
3. cria o ambiente virtual `.venv` dentro da pasta;
4. instala as dependências; com `--dev`, também pytest, httpx e PyInstaller.
Não rode o instalador com `sudo`: ele pede a senha só no passo que precisa. Para entender cada etapa, faça uma vez do jeito manual (veja "como instalar o aprendiz manualmente").

F: instalar-manual
A: instalar manualmente, sem script
Q: porque | fazer os passos à mão mostra o que o script faz | -> instalar-codigo
P: como instalar o aprendiz manualmente
P: como criar o ambiente virtual do aprendiz
P: instalar as dependências do aprendiz sem o instalador
R: O que o instalador faz, à mão (na pasta do projeto):
**Linux:**
```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements-dev.txt
```
**Windows (PowerShell):**
```
py -m venv .venv
.venv\Scripts\python -m pip install --upgrade pip
.venv\Scripts\python -m pip install -r requirements-dev.txt
```
- `requirements.txt` tem só o essencial (fastapi, uvicorn, rapidfuzz);
- `requirements-dev.txt` inclui o essencial (linha `-r requirements.txt`) mais pytest, httpx e PyInstaller;
- `requirements-janela.txt` é opcional: o pywebview, para a janela nativa.
Se preferir **ativar** o ambiente (para digitar só `python`): `source .venv/bin/activate` no Linux, `.venv\Scripts\Activate.ps1` no PowerShell. Se o PowerShell bloquear, rode uma vez `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

F: rodar
A: rodar o aprendiz pelo código, executar.sh
Q: porque | o script ativa o ambiente e abre o app | -> instalar-codigo
P: como rodar o aprendiz pelo código
P: como executar o aprendiz
P: o que faz python -m aprendiz
P: como abrir o aprendiz
P: rodar o aprendiz
R: Com o ambiente pronto, na pasta do projeto:
```bash
.venv/bin/python -m aprendiz                    # Linux
.venv\Scripts\python -m aprendiz                # Windows
bash executar.sh                                # atalho (instala na 1ª vez)
```
`python -m aprendiz` roda o arquivo `aprendiz/__main__.py`, que chama `main()` de `aprendiz/desktop.py`. Ele:
1. escolhe uma porta livre (a 8765, se puder);
2. sobe o servidor web local numa thread, em `127.0.0.1`;
3. abre a interface: janela nativa (se o pywebview estiver instalado), ou um Chromium em modo aplicativo, ou uma aba do navegador.
Opções úteis:
- `--modo servidor`: só o servidor; abra `http://127.0.0.1:8765` no navegador. É o melhor modo para estudar;
- `--modo navegador`: abre numa aba comum;
- `--porta 9000`: escolhe a porta.
Para parar: feche a janela (o servidor encerra sozinho em até 90 s) ou Ctrl+C no terminal.

F: docs-interativa
A: documentação interativa, /docs, swagger
Q: porque | o FastAPI gera uma página para testar cada rota | -> aprendiz-arquitetura:servidor
P: o que é a documentação interativa do aprendiz
P: como testar a api do aprendiz sem a interface
P: o que é a rota /docs
R: Com o Aprendiz rodando (`--modo servidor`), abra **`http://127.0.0.1:8765/docs`**. É a documentação que o FastAPI gera sozinho a partir do código: todas as rotas, os campos de cada pedido e um botão **Try it out** para chamar cada uma.
Experimente:
1. `POST /api/conhecimentos` com `{"pergunta": "senha do wifi", "conteudo": "casa123"}`;
2. `POST /api/chat` com `{"mensagem": "qual a senha do wifi?"}`;
3. veja no JSON da resposta o campo `meta.explicacao`: são as etapas do pipeline, as mesmas do **Monitor**.
Pelo terminal, o mesmo com `curl`:
```bash
curl -s -X POST http://127.0.0.1:8765/api/chat \
     -H "Content-Type: application/json" \
     -d '{"mensagem": "qual a senha do wifi?"}'
```

F: requisicoes
A: ver requisições no navegador, devtools
Q: porque | a aba Rede mostra o que a interface manda e recebe | -> aprendiz-codigo:enviar
P: como ver as requisições da interface no navegador
P: como usar o devtools com o aprendiz
R: A interface é uma página web, então dá para "espiar" tudo pelo **DevTools** do navegador:
1. com o Aprendiz em `--modo servidor`, abra `http://127.0.0.1:8765` no Chrome ou no Firefox;
2. aperte **F12** (ou Ctrl+Shift+I);
3. aba **Rede (Network)**: mande uma mensagem e clique na requisição `chat` para ver o JSON enviado (`Payload`) e o recebido (`Response`);
4. aba **Console**: erros de JavaScript aparecem aqui; você pode digitar JavaScript para testar;
5. aba **Elementos**: o HTML ao vivo; mude uma cor no CSS e veja na hora (sem salvar);
6. aba **Fontes (Sources)**: abra `app.js`, clique no número de uma linha para pôr um breakpoint e mande uma mensagem.
Foi por isso que o projeto escolheu uma interface web local: quem estuda vê cada pedido e cada resposta.

F: rodar-testes
A: rodar os testes, pytest, homologação
Q: porque | os testes confirmam que nada quebrou depois de uma mudança | -> prog-vocabulario:teste-automatizado

P: os testes do aprendiz estão falhando

P: rodar pytest no aprendiz
R: Na pasta do projeto, com as dependências de desenvolvimento instaladas:
```bash
.venv/bin/python -m pytest -q             # todos (Windows: .venv\Scripts\python -m pytest -q)
.venv/bin/python -m pytest tests/test_linguagem.py -v       # um arquivo
```

**Na 2.0:** depois dos testes, rode também a homologação: `python ferramentas/homologar.py ../aprendiz-addons --busca hibrido`.

F: dados
A: onde ficam os dados
Q: porque | os dados ficam fora da pasta do código | -> aprendiz-codigo:pasta-dados
P: onde ficam os dados do aprendiz

P: como apagar a memória do aprendiz
P: onde fica o banco de dados do aprendiz
P: onde o aprendiz guarda a memória
R: A memória inteira é **um arquivo SQLite**, `aprendiz.db`, fora da pasta do programa (assim, atualizar ou reinstalar não apaga nada):
- **Linux:** `~/.local/share/aprendiz/`
- **Windows:** `%APPDATA%\Aprendiz\` (cole no Explorador de Arquivos)

```bash
APRENDIZ_DADOS=/tmp/aprendiz-teste .venv/bin/python -m aprendiz --modo servidor
```
(No PowerShell: `$env:APRENDIZ_DADOS="C:\temp\aprendiz-teste"` antes do comando.)
Para começar do zero: use **Configurações → Resetar** (faz backup antes) ou apague o `aprendiz.db` com o app fechado. Para abrir o banco e olhar as tabelas: `sqlite3 ~/.local/share/aprendiz/aprendiz.db` e `.tables`, ou o DB Browser for SQLite.

F: externally-managed
A: erro externally managed environment, pip bloqueado
Q: porque | o sistema protege o Python dele; a saída é o ambiente virtual | -> python-avancado:venv
P: erro externally managed environment no aprendiz
P: erro python não encontrado no windows
P: problemas comuns ao instalar o aprendiz
R: Os problemas mais comuns e a saída:
- **"externally-managed-environment"** ao usar pip: você está no Python do sistema. Use o `.venv` (`.venv/bin/python -m pip ...`).
- **"No module named venv"** ou "ensurepip is not available" (Debian/Ubuntu): `sudo apt install python3-venv`.
- **Windows: "python não é reconhecido"** ou abre a Microsoft Store: reinstale marcando "Add to PATH", ou use `py` no lugar de `python`.
- **"Permission denied" no `./instalar.sh`**: use `bash instalar.sh`.
- **Linux sem sudo** (usuário fora do sudoers, comum em VMs Debian): o instalador pede a senha do **root** com `su`; se não souber, peça a quem administra para rodar o comando que ele mostra.
- **Porta ocupada:** o app escolhe outra sozinho; ou use `--porta 9000`.
- **ModuleNotFoundError: fastapi**: você rodou com um Python diferente do `.venv`.
- **Testes de API falhando com "httpx"**: instale o `requirements-dev.txt`.
O `docs/empacotamento.md` do projeto tem mais casos.

F: maquina-virtual
A: máquina virtual, virtualbox
Q: porque | uma máquina virtual permite testar sem mexer no sistema principal
P: como usar uma máquina virtual para estudar o aprendiz
P: como testar o aprendiz numa vm debian
R: Uma máquina virtual (VirtualBox, GNOME Boxes, Hyper-V) é ótima para testar a instalação do zero sem medo:
1. instale o VirtualBox e crie uma VM com a ISO do Debian, Ubuntu ou Fedora (2 GB de RAM e 20 GB de disco bastam);
2. instale os "Adicionais para Convidado" para ter área de transferência compartilhada;
3. dentro da VM: `sudo apt install git` (ou peça ao root, se o seu usuário não estiver no sudoers: `su -c "apt install git"`);
