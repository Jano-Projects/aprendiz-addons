# Programação 2 · Vocabulário e boas práticas
# Os nomes e as convenções que aparecem em qualquer projeto, em qualquer linguagem.

P: o que é camelcase
P: o que é camel case
P: o que é snake case
P: o que é pascalcase
P: o que é kebab case
P: quais os padrões de nomenclatura em programação
P: camelcase
P: snake_case
P: convenção de nomes
R: Como juntar palavras num nome, já que nomes não podem ter espaço:
- **camelCase:** a primeira minúscula, as outras com maiúscula: `nomeCompleto`. Comum em Java, JavaScript, C# (variáveis e métodos).
- **PascalCase:** todas com maiúscula: `NomeCompleto`. Usado para **classes** em quase todas as linguagens.
- **snake_case:** minúsculas separadas por `_`: `nome_completo`. Padrão do Python, de C e de SQL.
- **SCREAMING_SNAKE_CASE:** maiúsculas com `_`: `TAMANHO_MAXIMO`. Para **constantes**.
- **kebab-case:** minúsculas com hífen: `nome-completo`. Usado em nomes de arquivos, URLs, CSS e ids (os addons do Aprendiz usam: `prog-logica`).
O mais importante é seguir o padrão da linguagem e do projeto, sempre do mesmo jeito.

P: qual padrão de nome usar em python
P: o que é a pep 8
R: A **PEP 8** é o guia de estilo oficial do Python:
- variáveis, funções e módulos: `snake_case` (`calcular_media`, `banco.py`);
- classes: `PascalCase` (`Assistente`, `RespostaDireta`);
- constantes: `MAIUSCULAS` (`TAMANHO_MAXIMO`);
- "privado" por convenção: começa com `_` (`_atualizar_tabelas`);
- 4 espaços de indentação e linhas de até 79–99 caracteres.
Ferramentas como **ruff** e **black** conferem e formatam isso sozinhas. O código do Aprendiz segue a PEP 8, com nomes em português.

P: como dar bons nomes para variáveis
P: como nomear funções
P: boas práticas de nomenclatura
R: Um bom nome diz **o que é** sem precisar de comentário:
- variáveis são **substantivos**: `preco_total`, não `pt` nem `x`;
- funções são **verbos**: `calcular_frete()`, `buscar_usuario()`;
- booleanos são **perguntas**: `esta_ativo`, `tem_permissao`;
- listas no **plural**: `usuarios`; um item no singular: `for usuario in usuarios`;
- evite abreviações obscuras e nomes genéricos (`dados`, `coisa`, `temp2`);
- unidades no nome quando ajudam: `tempo_ms`, `tamanho_bytes`.
Nomes de uma letra só são aceitáveis em escopos minúsculos: `i` num laço curto, `x` e `y` em matemática.

P: devo programar em português ou inglês
P: nomes de variáveis em português
R: As duas escolhas são válidas; o importante é ser **consistente** dentro do projeto.
- **Inglês:** padrão em projetos abertos internacionais e nas bibliotecas; facilita contribuições de fora.
- **Português:** facilita o estudo para quem está começando e combina com projetos voltados ao público lusófono. O Aprendiz usa nomes em português de propósito, como material de estudo.
Misturar no mesmo nome (`getUsuario`) costuma ficar estranho. Palavras-chave da linguagem (`if`, `for`, `return`) são sempre em inglês, e tudo bem.

P: o que é comentário no código
P: como comentar código
P: quando escrever comentários
R: **Comentário** é texto que o computador ignora, escrito para pessoas.
- Python: `# comentário` e docstrings `"""..."""` no começo de funções e módulos;
- C/C++/Java/JS: `// uma linha` e `/* várias linhas */`;
- SQL: `-- comentário`.
Bons comentários explicam o **porquê** (uma decisão, um limite, um cuidado), não o **o quê**, que o próprio código já mostra:
```python
i += 1  # soma 1 em i               ← inútil
# A API limita 100 itens por página, por isso paginamos.  ← útil
```
Se precisa de um comentário para explicar o que uma linha faz, talvez um nome melhor resolva.

P: o que é indentação
P: para que serve indentar o código
R: **Indentação** é o recuo no começo das linhas para mostrar o que está dentro de quê (um bloco dentro de um `if`, de um laço, de uma função).
- Em **C, C++, Java**, os blocos são marcados por `{ }`; a indentação é para quem lê, mas é indispensável.
- Em **Python**, a indentação **é** a sintaxe: ela define o bloco. Use sempre 4 espaços (nunca misture tab e espaço).
O arquivo `.editorconfig` (o Aprendiz tem um) faz o editor usar o mesmo padrão para todo mundo.

P: o que é sintaxe e semântica
R: **Sintaxe** é a forma: as regras de escrita da linguagem (onde vai o `;`, como abrir um bloco).
**Semântica** é o significado: o que aquele código faz quando roda.
`x = "5" + 5` tem sintaxe válida em Python, mas a semântica é um erro (`TypeError`: não dá para somar texto e número).

P: o que é ide
P: o que é editor de código
P: qual ide usar para programar
P: ide
P: vs code
R: **IDE** (Ambiente de Desenvolvimento Integrado) junta editor, execução, depurador e ajuda num programa só.
- **VS Code:** gratuito, leve, serve para qualquer linguagem com extensões (Python, C/C++). Ótimo para começar.
- **PyCharm Community:** IDE completa para Python.
- **Code::Blocks / CLion / Visual Studio:** focados em C e C++ (o Visual Studio Community é gratuito, só no Windows).
- **Vim, Neovim, Nano:** editores de terminal, úteis em servidores.
O que uma IDE oferece: realce de sintaxe, autocompletar, ir para a definição, achar erros enquanto você digita e depurar com breakpoints.

P: o que é terminal
P: o que é linha de comando
P: o que é cli
P: o que é shell
R: O **terminal** é uma janela onde você digita comandos em vez de clicar. O programa que interpreta esses comandos é o **shell** (bash e zsh no Linux e macOS; PowerShell e cmd no Windows).
**CLI** (interface de linha de comando) é um programa feito para ser usado por comandos: `git`, `python`, `gcc`, `pip`.
Programadores usam muito o terminal porque é rápido, dá para automatizar com scripts e funciona até em servidores sem tela. Comandos básicos: `cd` (entrar numa pasta), `ls` ou `dir` (listar), `pwd` (onde estou).

P: o que é biblioteca em programação
P: o que é uma lib
P: o que é um pacote
P: o que é um módulo
R: **Biblioteca** (lib) é código pronto, escrito por outras pessoas, para você reaproveitar: datas, matemática, acesso a banco, criptografia.
- **Módulo:** um arquivo de código que pode ser importado (em Python, cada `.py` é um módulo).
- **Pacote:** um conjunto de módulos organizado numa pasta e, em geral, distribuído por um **gerenciador de pacotes**: `pip` (Python), `npm` (JavaScript), `apt`/`dnf` (Linux), `vcpkg` e `conan` (C/C++).
O Aprendiz depende de três bibliotecas externas: **FastAPI**, **Uvicorn** e **RapidFuzz** (listadas em `requirements.txt`).

P: o que é framework
P: diferença entre biblioteca e framework
P: framework
R: Com uma **biblioteca**, você chama o código dela quando quer. Com um **framework**, ele dita a estrutura e chama o **seu** código nos momentos certos ("não nos chame, nós chamamos você").
Exemplos: FastAPI, Django e Flask (web em Python), React (interface web), Qt (janelas em C++).
O Aprendiz usa o **FastAPI**: você escreve funções para cada rota (`/api/perguntar`), e o framework cuida de receber a requisição, validar e chamar a função certa.

P: o que é api
P: para que serve uma api
P: o que é api rest
P: o que significa api
P: api
R: **API** (Interface de Programação de Aplicações) é o "cardápio" que um programa oferece para outros programas usarem: quais pedidos aceita e o que devolve.
Uma **API web REST** usa o protocolo HTTP com endereços (rotas) e verbos:
- `GET /api/conhecimentos`: lista;
- `POST /api/ensinar`: cria;
- `PATCH`/`PUT`: altera;
- `DELETE /api/addons/x`: apaga.
Os dados normalmente vão em **JSON**. No Aprendiz, a tela (HTML e JavaScript) conversa com o Python exatamente assim, por uma API local em `127.0.0.1`.

P: o que é json
P: o que é xml
P: o que é yaml
P: json
R: São formatos de **texto** para guardar e trocar dados estruturados.
**JSON** (o mais usado hoje), com objetos `{}`, listas `[]`, textos, números, `true`/`false` e `null`:
```json
{"nome": "Ana", "idade": 30, "linguagens": ["Python", "C"]}
```
**XML** usa marcações como o HTML: `<pessoa><nome>Ana</nome></pessoa>`. Mais verboso; ainda comum em sistemas antigos e notas fiscais.
**YAML** usa indentação, fácil de ler; comum em arquivos de configuração (como o `publicar.yml` do GitHub Actions da loja de addons).
Os addons do Aprendiz são um ZIP com arquivos JSON dentro.

P: o que é http
P: o que é https
P: o que são os códigos de status http
R: **HTTP** é o protocolo da web: o cliente (navegador, app) faz uma **requisição** e o servidor devolve uma **resposta** com um código de status:
- **2xx sucesso:** 200 OK, 201 criado;
- **3xx redirecionamento:** 301, 302;
- **4xx erro de quem pediu:** 400 requisição inválida, 401 não autenticado, 403 proibido, 404 não encontrado;
- **5xx erro do servidor:** 500 erro interno, 503 indisponível.
**HTTPS** é o HTTP com criptografia (TLS): ninguém no caminho lê ou altera os dados. O Aprendiz só usa HTTP local (`127.0.0.1`), que não sai do computador.

P: o que é front end e back end
P: o que é full stack
R: - **Front-end:** a parte que a pessoa vê e usa: telas, botões. Na web: HTML, CSS e JavaScript.
- **Back-end:** a parte que roda no servidor: regras, banco de dados, API. Python, Java, C#, Node.js, PHP, Go…
- **Full stack:** quem trabalha nas duas.
O Aprendiz tem os dois, no mesmo computador: o back-end em Python (FastAPI) na pasta `aprendiz/`, e o front-end em `aprendiz/web/` (`index.html`, `estilo.css`, `app.js`).

P: o que é cliente servidor
P: o que é localhost
P: o que é 127.0.0.1
P: o que é uma porta de rede
R: No modelo **cliente-servidor**, o cliente pede e o servidor responde.
**localhost** (`127.0.0.1`) é o endereço do **próprio computador**: um servidor ouvindo nele não é acessível pela rede, só pela máquina. É por isso que o Aprendiz é offline e privado.
A **porta** é um número (0 a 65535) que diferencia os programas no mesmo endereço: a web usa 80 e 443, o PostgreSQL 5432. Um endereço completo fica `http://127.0.0.1:8000`.

P: o que é git
P: para que serve o git
P: o que é controle de versão
P: git
P: como usar git
R: **Git** é um sistema de **controle de versão**: guarda o histórico de todas as mudanças do projeto, permite voltar no tempo, ver quem mudou o quê e trabalhar em paralelo sem um apagar o trabalho do outro.
Os comandos do dia a dia:
```bash
git init                  # começa a versionar a pasta
git status                # o que mudou
git add arquivo.py        # prepara a mudança
git commit -m "mensagem"  # grava um ponto na história
git log --oneline         # a história
git diff                  # o que mudou, linha por linha
```
O **GitHub** (e o GitLab) é um site que hospeda repositórios Git na internet. Git é a ferramenta; GitHub é o lugar.

P: o que é commit
P: como escrever uma boa mensagem de commit
P: o que é conventional commits
R: **Commit** é uma "foto" do projeto num momento, com uma mensagem explicando a mudança.
Boas mensagens: um resumo curto no imperativo e, se precisar, um corpo explicando o porquê.
Muitos projetos usam o padrão **Conventional Commits**, com um tipo na frente:
- `feat:` funcionalidade nova;
- `fix:` correção de erro;
- `docs:` só documentação;
- `test:` testes;
- `refactor:` reorganização sem mudar o comportamento.
O próprio Aprendiz usa: `feat: normas da língua e revisão de texto (v0.8.0)`. Faça commits pequenos, de uma ideia cada.

P: o que é branch
P: o que é merge
P: o que é pull request
P: o que é fork
R: - **Branch (ramo):** uma linha de desenvolvimento separada. Você cria uma branch para uma funcionalidade, mexe à vontade e a `main` continua estável. `git switch -c minha-funcao`.
- **Merge:** juntar uma branch em outra. `git merge minha-funcao`. Se os dois lados mudaram a mesma linha, há um **conflito** para resolver à mão.
- **Fork:** sua cópia de um repositório de outra pessoa no GitHub.
- **Pull request (PR):** o pedido para que suas mudanças entrem no projeto original; é onde acontece a revisão de código.

P: o que é clone push e pull
P: diferença entre git pull e git fetch
R: - `git clone URL`: baixa um repositório inteiro, com a história.
- `git push`: envia seus commits para o repositório remoto (GitHub).
- `git fetch`: baixa as novidades do remoto **sem** mexer nos seus arquivos.
- `git pull`: `fetch` + `merge`: baixa e já junta na sua branch.
Exemplo: `git clone https://github.com/Jano-Projects/aprendiz-dev` baixa o código do Aprendiz.

P: o que é gitignore
P: para que serve o arquivo gitignore
R: O `.gitignore` lista arquivos que o Git **não** deve versionar: coisas geradas ou pessoais.
Exemplo para Python:
```
__pycache__/
*.pyc
.venv/
dist/
*.db
.env
```
Nunca versione senhas, chaves de API ou bancos com dados pessoais. Se uma senha for parar num commit, considere-a vazada e troque-a: apagar o arquivo depois não a tira da história.

P: o que é teste automatizado
P: o que é teste unitário
P: o que é teste de integração
P: por que escrever testes
P: testes automatizados
P: o que é teste de software
R: **Teste automatizado** é código que confere se outro código funciona. Roda em segundos, quantas vezes quiser.
- **Unitário:** testa uma peça pequena isolada (uma função).
- **Integração:** testa várias peças juntas (a API com o banco).
- **Ponta a ponta (E2E):** simula o usuário usando o sistema todo.
```python
def test_soma():
    assert soma(2, 3) == 5
```
Os testes dão coragem para mudar o código: se algo quebrar, você descobre na hora. O Aprendiz tem perto de 300 testes em `tests/`, rodados com `python -m pytest`.

P: o que é tdd
P: o que é desenvolvimento guiado por testes
R: **TDD** (Desenvolvimento Guiado por Testes) inverte a ordem:
1. **vermelho:** escreva um teste para o que ainda não existe; ele falha;
2. **verde:** escreva o mínimo de código para o teste passar;
3. **refatorar:** melhore o código, com o teste garantindo que nada quebrou.
Mesmo sem seguir TDD à risca, vale o hábito de escrever um teste para cada erro corrigido.

P: o que é refatoração
P: o que é refatorar código
R: **Refatorar** é melhorar a estrutura do código **sem mudar o que ele faz**: dar nomes melhores, quebrar uma função grande em menores, tirar repetição.
Regra de ouro: só refatore com testes passando, antes e depois. Faça um passo de cada vez e rode os testes a cada passo.

P: o que é código limpo
P: o que é clean code
R: **Código limpo** é o que outra pessoa (ou você daqui a seis meses) entende rápido. Alguns hábitos:
- nomes que dizem o que as coisas são;
- funções pequenas, que fazem uma coisa só;
- poucos parâmetros por função;
- sem código morto nem comentado "para depois";
- tratar os erros, não escondê-los;
- seguir o estilo do projeto.
O livro *Código Limpo*, de Robert C. Martin, popularizou o termo. Use as regras com bom senso, não como dogma.

P: o que é dry
P: o que é kiss
P: o que é yagni
R: Três princípios curtos:
- **DRY** (*Don't Repeat Yourself*): não repita a mesma lógica em vários lugares; se mudar, você teria de lembrar de todos.
- **KISS** (*Keep It Simple*): prefira a solução mais simples que resolve. Complexidade custa caro.
- **YAGNI** (*You Aren't Gonna Need It*): não construa hoje o que talvez precise um dia.
Eles se equilibram: repetir duas linhas parecidas às vezes é mais simples que uma abstração esperta.

P: o que é solid
P: quais são os princípios solid
R: **SOLID** são cinco princípios de design orientado a objetos:
- **S** (Responsabilidade única): uma classe tem um só motivo para mudar.
- **O** (Aberto/fechado): aberto para extensão, fechado para modificação. No Aprendiz, para criar um algoritmo de busca você escreve uma classe nova; não mexe nas existentes.
- **L** (Substituição de Liskov): uma subclasse deve funcionar onde a classe-mãe funciona.
- **I** (Segregação de interfaces): várias interfaces pequenas são melhores que uma gigante.
- **D** (Inversão de dependência): dependa de abstrações (uma "busca qualquer"), não de implementações concretas.

P: o que é paradigma de programação
P: o que é programação procedural
P: o que é programação orientada a objetos
P: o que é programação funcional
P: paradigmas de programação
R: **Paradigma** é um jeito de organizar o programa:
- **Procedural:** uma sequência de procedimentos (funções) que mexem em dados. C é o exemplo clássico.
- **Orientado a objetos (POO):** o programa é feito de **objetos** que juntam dados (atributos) e comportamento (métodos). Java, C#, C++ e Python.
- **Funcional:** funções puras (mesma entrada, mesma saída, sem efeitos colaterais), dados imutáveis, funções que recebem e devolvem funções. Haskell, Elixir; Python e JavaScript têm muitos recursos funcionais.
- **Declarativo:** você diz **o que** quer, não **como**. SQL é o exemplo: `SELECT nome FROM clientes WHERE cidade = 'Recife'`.
Linguagens modernas misturam paradigmas.

P: o que é classe e objeto
P: o que é atributo e método
P: o que é instância
P: o que é objeto em programação
P: o que é uma classe
R: **Classe** é o molde; **objeto** (ou **instância**) é uma coisa feita com o molde.
- **Atributos:** os dados do objeto (cor, modelo);
- **Métodos:** as ações que ele sabe fazer (acelerar, frear).
```python
class Carro:
    def __init__(self, modelo):
        self.modelo = modelo      # atributo
        self.velocidade = 0

    def acelerar(self, quanto):   # método
        self.velocidade += quanto

meu = Carro("Passat")             # instância
meu.acelerar(20)
```

P: o que é encapsulamento herança e polimorfismo
P: quais os pilares da orientação a objetos
P: o que é polimorfismo
P: o que é herança
P: o que é encapsulamento
R: Os quatro pilares da POO:
- **Abstração:** representar só o que importa do mundo real para o problema.
- **Encapsulamento:** esconder os detalhes internos e expor uma interface; o resto do código não mexe direto nos dados do objeto.
- **Herança:** uma classe aproveita e especializa outra (`Gato` herda de `Animal`).
- **Polimorfismo:** objetos diferentes respondem à mesma chamada, cada um do seu jeito.
No Aprendiz: todos os algoritmos de busca herdam de `AlgoritmoBusca` e têm um método `buscar`. O assistente chama `buscar` sem saber se é BM25 ou TF-IDF. Isso é polimorfismo.

P: o que é interface em programação
P: o que é classe abstrata
R: **Interface** (ou classe abstrata) define **o que** um tipo precisa saber fazer, sem dizer **como**. É um contrato.
```python
from abc import ABC, abstractmethod

class Forma(ABC):
    @abstractmethod
    def area(self) -> float: ...

class Quadrado(Forma):
    def __init__(self, lado):
        self.lado = lado
    def area(self):
        return self.lado ** 2
```
Não dá para criar uma `Forma()` direto, só as concretas. Em Java e C# há a palavra `interface`; em C++, classes com métodos `virtual ... = 0`.

P: o que é design pattern
P: o que é padrão de projeto
P: quais os padrões de projeto mais usados
R: **Padrões de projeto** são soluções conhecidas para problemas que se repetem, catalogados no livro da "Gangue dos Quatro" (GoF). Os mais comuns:
- **Strategy:** trocar o algoritmo em tempo de execução. O seletor de busca do Aprendiz é isso.
- **Registry/Factory:** criar objetos pelo nome. O decorador `@registrar` do Aprendiz registra cada algoritmo num dicionário.
- **Singleton:** uma única instância (use com cuidado).
- **Observer:** avisar vários interessados quando algo muda (eventos).
- **Adapter:** fazer uma interface encaixar em outra.
- **Repository:** esconder o acesso ao banco atrás de métodos (`banco.adicionar_conhecimento`).
Conheça os nomes para reconhecê-los, mas não force um padrão onde não precisa.

P: o que é bug
P: de onde vem o nome bug
R: **Bug** é um defeito no programa. A história famosa: em 1947, a equipe de Grace Hopper achou uma mariposa presa num relé do computador Mark II e colou no diário de bordo como "primeiro caso real de bug encontrado". O termo já era usado antes para defeitos, mas a anedota o popularizou.
**Debug** é remover bugs.

P: o que é deploy
P: o que é ambiente de produção
P: o que é homologação
R: - **Desenvolvimento:** a máquina de quem programa.
- **Homologação (staging):** uma cópia do ambiente real, onde se testa e os usuários validam antes de liberar.
- **Produção:** o ambiente que as pessoas usam de verdade.
**Deploy** é levar uma versão do código para um ambiente, principalmente para produção. Erros em produção custam caro; por isso existem os testes e a homologação.

P: o que é ci cd
P: o que é integração contínua
P: o que é github actions
R: - **CI (Integração Contínua):** a cada push, um servidor baixa o código, instala e roda os testes automaticamente. Se algo quebrar, todo mundo fica sabendo na hora.
- **CD (Entrega/Implantação Contínua):** se os testes passarem, a nova versão é publicada sozinha.
O **GitHub Actions** faz isso com arquivos YAML na pasta `.github/workflows/`. A loja de addons do Aprendiz usa: a cada push, `publicar.yml` confere todos os addons, gera o catálogo e publica o site. Se um addon for inválido, o site não é atualizado.

P: o que é versionamento semântico
P: o que significa versão 1.2.3
P: o que é semver
R: **Versionamento semântico** (SemVer): `MAIOR.MENOR.CORREÇÃO`, como `0.8.0`.
- **MAIOR:** mudanças que quebram a compatibilidade;
- **MENOR:** funcionalidades novas compatíveis;
- **CORREÇÃO:** só correções de erros.
Versões `0.x` indicam um projeto em desenvolvimento, em que a API ainda pode mudar. O Aprendiz segue SemVer e registra tudo no `CHANGELOG.md`.

P: o que é licença de software
P: o que é software livre
P: o que é código aberto
P: qual a diferença entre mit e gpl
R: A **licença** diz o que outras pessoas podem fazer com o seu código. Sem licença, ninguém pode legalmente reutilizar.
- **MIT:** permissiva: pode usar, mudar e vender, desde que mantenha o aviso de direitos autorais. O Aprendiz é MIT.
- **Apache 2.0:** permissiva, com cláusula de patentes.
- **GPL:** *copyleft*: quem distribuir versões modificadas precisa liberar o código sob a GPL também.
- **CC BY / CC0:** licenças Creative Commons, mais usadas para conteúdo (textos, dados). Os addons oficiais usam CC BY 4.0 ou CC0.
**Software livre** e **código aberto** são quase a mesma coisa na prática; o primeiro termo enfatiza a liberdade do usuário, o segundo, o modelo de desenvolvimento.

P: o que é sdk
P: o que é runtime
P: o que é dependência
R: - **SDK** (kit de desenvolvimento): o conjunto de ferramentas para criar programas para uma plataforma (compilador, bibliotecas, documentação). Ex.: Android SDK, .NET SDK.
- **Runtime:** o que precisa estar instalado para o programa **rodar** (o interpretador Python, a JVM, o .NET Runtime).
- **Dependência:** uma biblioteca que o seu programa precisa. Elas ficam listadas num arquivo (`requirements.txt`, `pyproject.toml`, `package.json`) para que qualquer um instale as mesmas.

P: o que é stack trace
P: o que é log
P: como ler uma mensagem de erro
R: - **Log:** mensagens que o programa grava enquanto roda ("iniciou", "erro ao abrir arquivo"), com níveis: DEBUG, INFO, WARNING, ERROR.
- **Stack trace / traceback:** o caminho de chamadas até o erro.
Como ler um traceback do Python:
1. vá à **última linha**: o tipo do erro e a mensagem (`KeyError: 'nome'`);
2. suba até a primeira linha que aponta para um arquivo **seu** (não de biblioteca);
3. abra esse arquivo nessa linha.
Copie a última linha numa busca: alguém quase sempre já teve o mesmo erro.

P: o que é stack overflow site
P: onde tirar dúvidas de programação
P: como pesquisar um erro
R: Bons lugares:
- a **documentação oficial** (docs.python.org, cppreference.com, sqlite.org): a fonte mais confiável;
- **Stack Overflow** (em inglês, e o pt.stackoverflow.com em português): perguntas e respostas de programação;
- as **issues** do projeto no GitHub, para erros de uma biblioteca.
Para pesquisar: copie a mensagem de erro sem os trechos específicos seus (nomes de arquivo, valores) e inclua a linguagem. Ao perguntar, mostre o código mínimo que reproduz o erro, o que você esperava e o que aconteceu.

P: o que é algoritmo determinístico
P: o que é heurística
R: **Determinístico:** a mesma entrada sempre produz a mesma saída, pelo mesmo caminho.
**Heurística:** uma regra prática que dá uma resposta boa na maioria das vezes, sem garantia de ser a ótima, mas rápida. Exemplos: o GPS que escolhe "um caminho bom" sem testar todos; o detector de dados pessoais da exportação do Aprendiz, que avisa sobre o que *parece* senha ou telefone.

P: o que é ascii e unicode
P: o que é utf-8
P: o que é encoding
R: Texto é guardado como números; a **codificação** (encoding) diz qual número é qual caractere.
- **ASCII:** 128 caracteres (letras sem acento, dígitos, símbolos). 'A' = 65.
- **Unicode:** uma tabela única com todos os caracteres de todas as línguas, mais emojis.
- **UTF-8:** o jeito mais comum de gravar Unicode em bytes; usa 1 byte para o ASCII e 2 a 4 para o resto ('ç' ocupa 2).
