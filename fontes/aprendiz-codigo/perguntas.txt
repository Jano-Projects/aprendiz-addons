F: pasta-dados
A: onde guardar os dados, pasta do usuário
Q: porque | cada sistema tem um lugar certo para dados de programas, e o app respeita isso
P: como o aprendiz descobre onde guardar os dados
P: explica a função pasta_dados do config.py
R: Em `aprendiz/config.py`:
```python
def pasta_dados() -> Path:
    personalizada = os.environ.get("APRENDIZ_DADOS")
    if personalizada:
        pasta = Path(personalizada)
    elif sys.platform.startswith("win"):
        pasta = Path(os.environ.get("APPDATA", Path.home())) / NOME_APP
    elif sys.platform == "darwin":
        pasta = Path.home() / "Library" / "Application Support" / NOME_APP
    else:
        base = os.environ.get("XDG_DATA_HOME", Path.home() / ".local" / "share")
        pasta = Path(base) / "aprendiz"
    pasta.mkdir(parents=True, exist_ok=True)
    return pasta
```
O que cada comando faz:
- `os.environ.get("X", padrao)`: lê uma **variável de ambiente**, com valor padrão se não existir. É o que permite `APRENDIZ_DADOS=/tmp/teste` para estudar sem tocar na memória real;
- `sys.platform`: o sistema: `"win32"`, `"darwin"` (macOS) ou `"linux"`;
- `Path.home()`: a pasta do usuário; o operador `/` junta caminhos do jeito certo em cada sistema;
- `mkdir(parents=True, exist_ok=True)`: cria a pasta e as de cima, sem erro se já existir;
- `-> Path`: anotação de tipo do retorno.

F: porta
A: porta do servidor, porta livre
Q: porque | pedir a porta 0 ao sistema garante uma porta livre
P: como o aprendiz escolhe a porta do servidor
P: explica a função escolher_porta
R: Em `aprendiz/desktop.py`:
```python
def escolher_porta(preferida: int) -> int:
    for porta in (preferida, 0):
        with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
            if not sys.platform.startswith("win"):
                s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
            try:
                s.bind(("127.0.0.1", porta))
                return s.getsockname()[1]
            except OSError:
                continue
    raise RuntimeError("Nenhuma porta livre encontrada.")
```
- `socket.socket(AF_INET, SOCK_STREAM)`: cria um socket TCP (IPv4);
- `bind(("127.0.0.1", porta))`: tenta "ocupar" a porta só no próprio computador; se outro programa já a usa, lança `OSError`;
- a porta **0** pede ao sistema "qualquer porta livre", e `getsockname()[1]` diz qual veio;
- o `with` fecha o socket no fim: ele só serviu para testar;
- `SO_REUSEADDR` (fora do Windows) evita que conexões recém-fechadas façam a porta parecer ocupada;
- `for ... in (preferida, 0)` + `continue` + `raise` no fim: tenta a preferida, depois qualquer uma, e só então desiste.

F: thread
A: servidor numa thread, threading
Q: porque | o servidor roda em paralelo enquanto a janela ocupa a thread principal | -> python-avancado:threads
P: como o aprendiz sobe o servidor numa thread
P: explica a função iniciar_servidor
R: Em `aprendiz/desktop.py`:
```python
def iniciar_servidor(porta: int):
    app = criar_app()
    cfg = uvicorn.Config(app, host="127.0.0.1", port=porta,
                         log_level="warning", access_log=False)
    servidor = uvicorn.Server(cfg)
    threading.Thread(target=servidor.run, daemon=True).start()

    limite = time.time() + 20
    while not servidor.started:
        if time.time() > limite:
            raise RuntimeError("O servidor demorou demais para iniciar.")
        time.sleep(0.05)
    return servidor, app
```
- `uvicorn.Server(cfg).run`: o servidor HTTP que executa a aplicação FastAPI;
- `threading.Thread(target=..., daemon=True).start()`: roda o servidor em **paralelo**, liberando a thread principal para abrir a janela. `daemon=True` faz a thread morrer junto com o programa;
- o `while not servidor.started` espera o servidor ficar pronto, conferindo a cada 50 ms, com um limite de 20 s;
- devolve uma **tupla** `(servidor, app)`; quem chama desempacota: `servidor, app = iniciar_servidor(porta)`. No fim, `servidor.should_exit = True` pede ao Uvicorn que pare.

F: janela-fechada
A: janela fechada, encerrar o app
Q: porque | quando a janela fecha, o app encerra o servidor junto
P: como o aprendiz sabe que a janela foi fechada
P: como funciona o sinal de vida do aprendiz
R: Três pedaços trabalham juntos:
**1. A página** (`web/app.js`) avisa que está viva a cada 10 s:
```javascript
function enviarSinal() {
  fetch("/api/sinal", { method: "POST" }).catch(() => {});
}
setInterval(enviarSinal, 10000);
```
**2. A API** (`api/servidor.py`) anota a hora do último sinal:
```python
@app.post("/api/sinal", include_in_schema=False)
def sinal():
    app.state.ultimo_sinal = time.monotonic()
    return {"ok": True}
```
**3. O desktop** (`esperar_interface`) confere a cada segundo; passou de 90 s sem sinal, encerra. Se o relógio pular mais de 10 s de uma volta para outra, o computador provavelmente hibernou, e esse tempo não conta.
`time.monotonic()` é um relógio que **nunca anda para trás** (ao contrário do relógio do sistema, que pode ser ajustado): o certo para medir intervalos. `app.state` é o lugar do FastAPI para guardar dados da aplicação.

F: criar-app
A: criar_app, fábrica do fastapi
Q: porque | montar o app numa função deixa os testes criarem um app novo a cada teste | -> python-avancado:fastapi
P: como funciona a função criar_app
P: explica o criar_app do servidor
R: Em `aprendiz/api/servidor.py`:
```python
def criar_app(caminho_banco: str | Path | None = None) -> FastAPI:
    banco = Banco(caminho_banco or config.caminho_banco())
    assistente = Assistente(banco)
    app = FastAPI(title="Aprendiz", version=config.VERSAO)
    app.state.banco = banco
    app.state.assistente = assistente
    app.mount("/static", StaticFiles(directory=config.PASTA_WEB), name="static")

    @app.get("/", include_in_schema=False)
    def pagina_inicial():
        return FileResponse(config.PASTA_WEB / "index.html")

    @app.post("/api/chat")
    def chat(pedido: PedidoChat):
        try:
            return assistente.responder(pedido.mensagem, pedido.conversa_id,
                                        pedido.busca, pedido.resposta)
        except ValueError as erro:
            raise HTTPException(400, str(erro)) from erro
    ...
    return app
```
Ideias importantes:
- é uma **fábrica** (*factory*): uma função que monta e devolve a aplicação. Receber o caminho do banco permite que cada teste crie uma app com um banco descartável;
- as rotas são **funções internas** (closures) que "enxergam" `banco` e `assistente` da função de fora;
- `@app.post("/api/chat")` registra a função como a rota; o parâmetro `pedido: PedidoChat` diz ao FastAPI para validar o JSON do corpo com esse modelo;
- o dicionário devolvido vira JSON sozinho;
- `HTTPException(400, ...)` vira uma resposta de erro HTTP; `raise ... from erro` preserva a causa original no traceback;
- `app.mount("/static", StaticFiles(...))` serve os arquivos da pasta `web/`.

F: banco
A: classe banco, banco por dentro
Q: porque | concentra todo o SQL num lugar só | -> prog-banco-dados:sqlite
P: como funciona a classe banco por dentro
P: explica o __init__ do banco
R: Em `aprendiz/memoria/banco.py`:
```python
class Banco:
    def __init__(self, caminho: str | Path):
        self.caminho = str(caminho)
        self._con = sqlite3.connect(self.caminho, check_same_thread=False)
        self._con.row_factory = sqlite3.Row
        self._con.execute("PRAGMA foreign_keys = ON")
        self._con.execute("PRAGMA journal_mode = WAL")
        self._trava = threading.RLock()
        self.versao_conhecimento = 0
        self.versao_linguagem = 0
        with self._trava:
            self._con.executescript(ESQUEMA)
            self._con.commit()
            self._migrar()
        if self.obter_meta("semeado") is None:
            self.semear()
```
- `check_same_thread=False`: o servidor web usa várias threads, e por padrão o `sqlite3` só aceita a thread que abriu a conexão;
- por isso, **todo** acesso passa por `with self._trava:`. O `RLock` (trava reentrante) deixa a mesma thread travar de novo sem se bloquear, útil quando um método do banco chama outro;
- `row_factory = sqlite3.Row`: linhas acessíveis pelo nome (`linha["id"]`);
- `PRAGMA foreign_keys = ON`: o SQLite só respeita chaves estrangeiras com isso ligado;
- `journal_mode = WAL`: leituras não bloqueiam escritas;
- `executescript(ESQUEMA)`: roda todos os `CREATE TABLE IF NOT EXISTS` de uma vez;
- `_migrar()` atualiza bancos antigos; `semear()` grava a linguagem inicial na primeira vez;
- o `_` no começo de `_con` e `_trava` avisa: "uso interno, não mexa de fora".

F: migracoes
A: migrações, versão do esquema, banco antigo
Q: porque | bancos de versões antigas ganham as colunas novas ao abrir o app, como a teia na 2.0 | -> banco
P: como funcionam as migrações do banco do aprendiz
P: explica o _migrar
R: `CREATE TABLE IF NOT EXISTS` não acrescenta colunas novas a uma tabela que já existe. Então, a cada mudança de estrutura, `Banco._migrar()` ganha um passo **idempotente** (rodar de novo não estraga nada):
```python
colunas = {linha["name"] for linha in c.execute("PRAGMA table_info(conhecimentos)")}
if "addon_id" not in colunas:               # versão 0.1 → 0.2 (addons)
    c.execute("ALTER TABLE conhecimentos ADD COLUMN addon_id TEXT")
...
c.execute("INSERT OR REPLACE INTO meta VALUES ('versao_esquema', '8')")
```
- `PRAGMA table_info(tabela)` lista as colunas; a **compreensão de conjunto** `{... for ...}` junta os nomes;
- só acrescenta a coluna se ela faltar;
- para mudar um `CHECK` (que o SQLite não altera), `_ampliar_check` renomeia a tabela, recria pelo esquema novo, copia os dados **pelos nomes das colunas** e apaga a antiga;
- a versão da estrutura fica gravada em `meta.versao_esquema`.
Assim, quem atualiza o app de qualquer versão antiga continua com a memória intacta.

F: salvar
A: salvar conhecimento, gravar
Q: porque | grava o texto e os radicais para a busca, e na 2.0 também a teia | -> banco
P: como o banco salva um conhecimento
P: explica salvar_conhecimento e o índice fts5
R: ```python
def salvar_conhecimento(self, conteudo, tipo="nota", pergunta=None, origem="manual",
                        texto_busca="", id=None, addon_id=None):
    id = id or novo_id()
    momento = agora()
    with self._trava:
        existente = self._con.execute(
            "SELECT criado_em FROM conhecimentos WHERE id = ?", (id,)).fetchone()
        criado = existente["criado_em"] if existente else momento
        self._con.execute(
            "INSERT OR REPLACE INTO conhecimentos (id, tipo, pergunta, conteudo, origem, "
            "texto_busca, criado_em, atualizado_em, addon_id) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)",
            (id, tipo, pergunta, conteudo, origem, texto_busca, criado, momento, addon_id))
        self._con.execute("DELETE FROM conhecimentos_fts WHERE id = ?", (id,))
        self._con.execute("INSERT INTO conhecimentos_fts (id, texto) VALUES (?, ?)",
                          (id, texto_busca))
        self._con.commit()
    self.versao_conhecimento += 1
    return self.obter_conhecimento(id)
```
- `id or novo_id()`: se não veio id, gera um UUID (`uuid.uuid4().hex`);
- `INSERT OR REPLACE`: cria, ou substitui se o id já existir (editar = salvar de novo), preservando a data de criação;
- os `?` são **parâmetros**: os valores nunca viram parte do SQL (sem *SQL injection*);
- o índice **FTS5** é mantido à mão: apaga a linha antiga e insere a nova;
- `versao_conhecimento += 1` avisa os caches (TF-IDF, Fuzzy, vocabulário) que a base mudou.

F: bm25-banco
A: busca bm25 no banco, fts5
Q: porque | o SQLite já traz o BM25 no índice FTS5 | -> aprendiz-algoritmos:bm25
P: como o banco faz a busca bm25
P: explica a função buscar_fts
R: ```python
def buscar_fts(self, consulta: str, limite: int = 10) -> list[dict[str, Any]]:
    return self._consultar(
        "SELECT f.id, bm25(conhecimentos_fts) AS score FROM conhecimentos_fts f "
        "JOIN conhecimentos c ON c.id = f.id "
        "LEFT JOIN addons a ON a.id = c.addon_id "
        "WHERE conhecimentos_fts MATCH ? AND (c.addon_id IS NULL OR a.ativo = 1) "
        "ORDER BY score LIMIT ?",
        (consulta, limite))
```
- `MATCH ?` usa o índice FTS5 com a expressão montada pelo algoritmo (`"horari" OR "farmac"`);
- `bm25(conhecimentos_fts)` é a função do próprio SQLite que calcula a nota BM25, em C. Ela devolve números **negativos** (menor = mais relevante), por isso `ORDER BY score` crescente;
- o `LEFT JOIN addons` + `(c.addon_id IS NULL OR a.ativo = 1)` filtra, dentro do SQL, os conhecimentos de addons **desativados**, para eles nunca "empurrarem" resultados válidos para fora do limite;
- `_consultar` é o método auxiliar que trava, executa e transforma cada linha em dicionário: `[dict(l) for l in cursor.fetchall()]`.

F: normalizar-codigo
A: função normalizar, código da normalização
Q: porque | junta acentos, pontuação, nomes de linguagem e, na 2.0, números e contas | -> aprendiz-algoritmos:numeros
P: como funciona o normalizar do aprendiz
P: explica o código do normalizador
R: Em `aprendiz/linguagem/normalizador.py`:
```python
_NAO_ALFANUMERICO = re.compile(r"[^a-z0-9]+")

def remover_acentos(texto: str) -> str:
    decomposto = unicodedata.normalize("NFKD", texto)
    return "".join(c for c in decomposto if not unicodedata.combining(c))

def normalizar(texto: str) -> str:
    texto = remover_acentos(texto.lower())
    texto = _PREFIXO_HIFEN.sub(r"\1", texto)      # "wi-fi" → "wifi"
    texto = _MAIS_MAIS.sub(r"\1pp", texto)        # "c++" → "cpp"
    texto = _SUSTENIDO.sub(r"\1sharp", texto)     # "c#" → "csharp"
    return _NAO_ALFANUMERICO.sub(" ", texto).strip()
```
- `unicodedata.normalize("NFKD", ...)` separa "ç" em "c" + cedilha; o `join` com o gerador descarta os caracteres "combinantes" (os acentos);
- `re.compile` prepara a regex uma vez só, no carregamento do módulo; `.sub(" ", texto)` troca tudo que não é letra ou número por espaço;
- `\1` na troca é "o que o grupo 1 capturou";
- `.strip()` tira os espaços das pontas.
Depois, `Linguagem.processar()` faz o resto: tokens, abreviações, correção de digitação, expressões, sinônimos, lemas, stopwords e radicais, guardando cada etapa num `TextoProcessado` (uma `@dataclass`), que o **Monitor** mostra.

F: correcao-codigo
A: código da correção, process.extract
Q: porque | busca as palavras mais parecidas e desempata pelo par com a vizinha | -> aprendiz-algoritmos:correcao
P: como funciona a correção de digitação no código
P: explica o _corrigir do normalizador
R: ```python
def _corrigir(self, tokens, registro):
    if not self.vocabulario:
        return tokens
    saida = []
    for t in tokens:
        if (len(t) >= self.TAMANHO_MINIMO_CORRECAO      # 4 letras ou mais
                and not t.isdigit()
                and t not in self.vocabulario           # já é conhecida? não corrige
                and t not in self.stopwords
                and t not in self.sinonimos
                and not self.lexico.conhece(t)):        # palavra que existe no português
            achado = process.extractOne(
                t, self.vocabulario, scorer=fuzz.ratio,
                score_cutoff=self.SIMILARIDADE_MINIMA_CORRECAO)   # 80 de 100
            if achado:
                registro[t] = achado[0]
                t = achado[0]
        saida.append(t)
    return saida
```
- `process.extractOne` (RapidFuzz) compara a palavra com **todo** o vocabulário e devolve a mais parecida, se passar do corte; o núcleo é em C++, por isso é rápido;
- o **vocabulário** são as palavras que aparecem na base de conhecimento: o corretor só sugere o que o assistente conhece;
- `registro[t] = ...` anota a troca, que aparece no painel de explicação;
- a condição longa é quebrada em várias linhas dentro de parênteses, uma regra por linha.

F: stemmer-codigo
A: código do stemmer, radical
Q: porque | corta sufixos por regras do português | -> aprendiz-algoritmos:radicalizador
P: como funciona o radical no código do stemmer
P: explica a função radical
R: Em `aprendiz/linguagem/stemmer.py`:
```python
Regra = tuple[str, int, str]          # (sufixo, tamanho mínimo do radical, troca)
PLURAL: list[Regra] = [("oes", 3, "ao"), ("ais", 1, "al"), ..., ("s", 2, "")]

@lru_cache(maxsize=50_000)
def radical(palavra: str) -> str:
    if len(palavra) <= 3 or palavra.isdigit():
        return palavra
    if palavra.endswith("s"):
        palavra, _ = _aplicar(palavra, PLURAL)
    if palavra.endswith("a"):
        palavra, _ = _aplicar(palavra, FEMININO)
    palavra, _ = _aplicar(palavra, GRAU)
    palavra, mudou = _aplicar(palavra, SUBSTANTIVO)
    if not mudou:
        palavra, mudou = _aplicar(palavra, VERBO)
    if not mudou and palavra.endswith(VOGAIS_FINAIS) and len(palavra) > 3:
        palavra = palavra[:-1]
    return palavra
```
- `Regra = tuple[str, int, str]` cria um **apelido de tipo**;
- as regras são **dados** (listas de tuplas), e uma função genérica `_aplicar` percorre a lista e aplica a primeira que servir, devolvendo `(palavra, mudou)`;
- `palavra, _ = ...`: o `_` descarta o valor que não interessa;
- `@lru_cache(maxsize=50_000)`: guarda os resultados; como as mesmas palavras aparecem o tempo todo, cada uma é calculada uma vez;
- `palavra[:-1]` corta a última letra; `50_000` é só 50000 com separador de leitura.

F: bayes-codigo
A: código do naive bayes
Q: porque | conta palavras por intenção e escolhe a mais provável | -> aprendiz-algoritmos:cumprimentos
P: como funciona o naive bayes no código
P: explica o código do classificador de intenções
R: Em `aprendiz/linguagem/intencoes.py`, o treino conta palavras por intenção e guarda **logaritmos**:
```python
contagem_intencao: Counter[str] = Counter()
contagem_palavras: dict[str, Counter[str]] = defaultdict(Counter)
for intencao, termos in exemplos:
    contagem_intencao[intencao] += 1
    contagem_palavras[intencao].update(termos)
    self.vocabulario.update(termos)
total = sum(contagem_intencao.values())
v = len(self.vocabulario) or 1
self.log_prior = {i: math.log(n / total) for i, n in contagem_intencao.items()}
for intencao, contagem in contagem_palavras.items():
    denominador = sum(contagem.values()) + v
    self.log_verossimilhanca[intencao] = {
        p: math.log((n + 1) / denominador) for p, n in contagem.items()}   # Laplace: +1
```
E a classificação soma os logs e converte com **softmax**:
```python
pontuacoes[intencao] = prior + sum(tabela.get(t, padrao) for t in conhecidos)
maior = max(pontuacoes.values())
exps = {i: math.exp(p - maior) for i, p in pontuacoes.items()}
```
- `Counter` conta; `defaultdict(Counter)` cria um contador novo na primeira vez que uma intenção aparece;
- `.update(lista)` soma as ocorrências de uma vez;
- compreensões de dicionário `{k: v for ...}` montam as tabelas;
- subtrair o `maior` antes do `exp` evita estouro numérico (os valores ficam ≤ 0).
A matemática completa está no addon **Como os algoritmos pensam**.

F: registro
A: registro de algoritmos, @registrar, decorador
Q: porque | o decorador põe cada algoritmo na lista do seletor sem mexer em outro arquivo | -> python-avancado:decorador
P: como funciona o registro de algoritmos no código
P: explica o decorador registrar
R: Em `aprendiz/algoritmos/base.py`:
```python
BUSCAS: dict[str, AlgoritmoBusca] = {}
RESPOSTAS: dict[str, AlgoritmoResposta] = {}

def registrar(cls):
    instancia = cls()
    if isinstance(instancia, AlgoritmoBusca):
        BUSCAS[instancia.nome] = instancia
    elif isinstance(instancia, AlgoritmoResposta):
        RESPOSTAS[instancia.nome] = instancia
    else:
        raise TypeError(f"{cls.__name__} não é um algoritmo de busca nem de resposta")
    return cls
```
E em cada algoritmo:
```python
@registrar
class BuscaBM25(AlgoritmoBusca):
    nome = "bm25"
    ...
```
- um **decorador de classe** recebe a classe e devolve a classe (aqui, a mesma), aproveitando para fazer algo: criar uma instância e guardá-la no dicionário pelo `nome`;
- isso acontece no **import** do módulo; por isso `algoritmos/busca/__init__.py` importa `bm25, tfidf, fuzzy, hibrido`, e a ordem dos imports é a ordem no seletor;
- `isinstance` confere de que tipo é; `cls.__name__` é o nome da classe;
- o pipeline escolhe pelo nome: `BUSCAS[busca].buscar(...)`. É o **padrão Strategy** com um **registro** (*registry*).

F: candidato

F: codigo-bm25
A: código da busca bm25
Q: exemplo-de | um algoritmo de busca completo e pequeno | -> aprendiz-algoritmos:bm25
P: explica o código da busca bm25 do aprendiz
P: como o bm25.py monta a busca
R: ```python
def buscar(self, consulta, ctx, limite=5):
    termos = list(dict.fromkeys(consulta.radicais))    # únicos, mantendo a ordem
    if not termos:
        return []
    expressao = " OR ".join(f'"{t}"' for t in termos)
    linhas = ctx.banco.buscar_fts(expressao, limite * 3)
    candidatos = []
    for linha in linhas:
        doc = ctx.banco.obter_conhecimento(linha["id"])
        if not doc:
            continue
        cob = cobertura(termos, set(doc["texto_busca"].split()))
        candidatos.append(Candidato(conhecimento=doc,
                                    pontuacao=round(-linha["score"], 4),
                                    confianca=round(cob, 4),
                                    detalhes={"bm25": round(-linha["score"], 4),
                                              "cobertura": round(cob, 4)}))
    candidatos.sort(key=lambda c: (c.confianca, c.pontuacao), reverse=True)
    return candidatos[:limite]
```
- `dict.fromkeys(lista)` é um truque para tirar repetidos **mantendo a ordem** (um `set` perderia a ordem);
- `" OR ".join(...)` monta `"horari" OR "farmac"`, a sintaxe do FTS5; as aspas tratam cada radical como literal;
- pede `limite * 3` ao banco porque depois reordena pela cobertura;
- `-linha["score"]` inverte o sinal do BM25 do SQLite (que é negativo);
- ordena por uma **tupla** `(confiança, pontuação)`: primeiro a cobertura, e o BM25 desempata.

F: etapas
A: classe etapas, explicação, tempos
Q: porque | cada etapa anota dados e tempo, e isso vira o Monitor
P: explica a classe etapas do assistente
P: como o aprendiz mede o tempo de cada etapa
R: ```python
class Etapas:
    def __init__(self) -> None:
        self.lista: list[dict[str, Any]] = []
        self.meta: dict[str, Any] = {}
        self._inicio_total = time.perf_counter()
        self._inicio = self._inicio_total

    def marcar(self, nome: str, dados: dict[str, Any]) -> None:
        agora = time.perf_counter()
        self.lista.append({"nome": nome, "ms": round((agora - self._inicio) * 1000, 2),
                           "dados": dados})
        self._inicio = agora

    @property
    def total_ms(self) -> float:
        return round((time.perf_counter() - self._inicio_total) * 1000, 2)
```
- `time.perf_counter()`: o relógio de maior precisão disponível, feito para medir durações curtas;
- cada `marcar` mede o tempo **desde a marcação anterior** e reinicia o cronômetro;
- `@property total_ms` é calculado na hora em que é lido.
A `lista` vai inteira para `meta.explicacao.etapas`, e o **Monitor** mostra cada etapa com os seus milissegundos. Na 2.4, `Etapas` também tem um **ouvinte**, chamado a cada etapa: é assim que a rota `/api/chat/fluxo` envia o pipeline ao vivo.

F: regex-ensino
A: expressões regulares de ensino, aprenda que
Q: porque | cada jeito de ensinar tem um padrão de texto | -> python-avancado:regex
P: explica as expressões regulares de ensino do aprendiz
P: como o aprendiz entende aprenda que
R: No topo de `core/assistente.py`:
```python
_VERBOS_ENSINO = r"(?:aprenda|aprende|memorize|memoriza|lembre(?:-se)?|anote|guarde|grave|registre)"

PADRAO_PAR = re.compile(r"^\s*pergunta\s*:\s*(?P<p>.+?)\s*resposta\s*:\s*(?P<r>.+)$",
                        re.I | re.S)
```
Lendo o `PADRAO_PAR` pedaço a pedaço:
- `^\s*pergunta\s*:\s*`: começa com "pergunta:", aceitando espaços em volta;
- `(?P<p>.+?)`: um **grupo com nome** `p`, com `+?` **preguiçoso** (pega o mínimo possível, para não engolir o "resposta:");
- `resposta\s*:\s*(?P<r>.+)$`: o resto, até o fim, é a resposta;
- `re.I` (`re.IGNORECASE`): maiúsculas ou minúsculas; `re.S` (`re.DOTALL`): o `.` também pega quebras de linha;
- `(?:...)` é um grupo **sem captura** (só agrupa as alternativas com `|`).
No uso: `m = PADRAO_PAR.match(mensagem)` e depois `m["p"]`, `m["r"]`. As outras duas (`PADRAO_FATO`, "aprenda que X é Y", e `PADRAO_NOTA`, "anote: …") usam a mesma lista de verbos.

R: Em `aprendiz/configuracoes.py`, os validadores são **fábricas de funções** (closures):
```python
def _numero(minimo: float, maximo: float) -> Callable[[Any], float]:
    def validar(valor: Any) -> float:
        if isinstance(valor, bool) or not isinstance(valor, (int, float)):
            raise ValueError("precisa ser um número")
        if not minimo <= valor <= maximo:
            raise ValueError(f"precisa estar entre {minimo} e {maximo}")
        return round(float(valor), 3)
    return validar

@dataclass(frozen=True)
class Definicao:
    chave: str
    tipo: str
    titulo: str
    descricao: str
    padrao: Any
    validar: Callable[[Any], Any]
    extras: dict = field(default_factory=dict)
```
- `_numero(0.05, 1.0)` **devolve uma função** que "lembra" o mínimo e o máximo: isso é uma closure;
- `isinstance(valor, bool)` vem antes porque em Python `True` também é um `int` (vale 1);
- `minimo <= valor <= maximo`: comparação encadeada;
- `@dataclass(frozen=True)`: a definição não pode ser alterada depois de criada;
- `Callable[[Any], float]`: o tipo "função que recebe qualquer coisa e devolve float";
- o dicionário `DEFINICOES = {d.chave: d for d in [...]}` é a **lista fechada**.

R: ```javascript
function escapar(texto) {
  return texto
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;")
    .replace(/'/g, "&#39;");
}

function emLinha(texto) {          // o texto já chega escapado
  return texto
    .replace(/`([^`]+)`/g, "<code>$1</code>")
    .replace(/\*\*([^*]+)\*\*/g, "<strong>$1</strong>");
}
```
A regra de ouro: **escapar primeiro, formatar depois**. Se alguém ensinar `<script>alert(1)</script>` (ou um addon trouxer isso), o `<` vira `&lt;` e aparece como texto na tela, nunca executa. Só depois o renderizador transforma as marcações seguras (negrito, itálico, código, listas) em HTML que ele mesmo escreve.
O texto é primeiro dividido pelas cercas de três crases: as partes ímpares são blocos de código (`<pre><code>`), escapadas e sem formatação. As expressões regulares com `/g` trocam **todas** as ocorrências; `$1` é o grupo capturado.

P: como funciona o teia.py
R: `aprendiz/core/teia.py` tem duas partes:
- `Teia._atualizar()` monta um índice `(addon, ref) → conhecimento` com os conhecimentos ativos que têm teia, e só refaz quando `versao_conhecimento` muda;
- `Teia.percorrer()` faz uma **busca em largura**: uma fila começa no fragmento achado; para cada porquê, resolve a ligação, marca como visto, aplica os freios (profundidade, raiz, assunto, causa x lado) e põe na fila o destino que pode descer.
O resultado é um `Caminho` com uma lista de `Passo` (nível, relação, texto, destino e o motivo do corte, quando houver), que a resposta Trabalhada transforma em texto.
